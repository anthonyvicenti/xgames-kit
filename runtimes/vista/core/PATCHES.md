# gf-vista core patches

Every change to the vendored Tidewater source (`UPSTREAM.json`: 4811ba48). Each edit in the code carries the marker
`gf-vista:` naming the patch number here, so a later upstream version can be vendored and these replayed. The build
agent never edits the core (PLAN §7); only the core track does, and adds a row here.

Patch #6, second pass (2026-10-13: "the place doesn't feel different where it counts"): the harbour moves. `Place.js`
gains a harbour frame (`recipe.harbour = { x, z, heading }`: where upstream's pier foot lands and how far its frame is
turned) with `toWorld` / `toLocal` / `worldBox` (the identity for upstream's island, returning the very same numbers).
Everything upstream laid out round its pier and bay reads through it: TerrainData's beach zone, valley, pier channel,
cusps, bar, dunes, scarp and their scan boxes; the village builds its pier (`Pier.js`: `arch` optional, the head's
outfitting follows the head wherever the pier ends, walkway gear only on walkway), a new stone or concrete jetty
(`Jetty.js`) or a short dock in that frame and sets it down (`Village._inFrame`: local builder, proxied terrain,
colliders and props, geometry, lights and pivots moved after), and the plaza, boardwalk route, boathouse and stalls
(`App.js` sets the fish stand and chandlery from `recipe.stalls`) where the place puts them; `Rocks`, `Reef`, `Scatter`,
`DebrisPlacement`, `Crabs`, `Shorebirds` (simulated in the harbour frame, drawn in the world), `Birds`, `Fish`,
`WhaleBrain`, `Game`, `Player`, `SoundScape` and `App.nearPier` read the bay through it. Nature: `recipe.nature` tints
the terrain's sand, sea floor and rock (`Terrain.js`, whose surface WGSL is now built with the terrain instead of at
module load, so it also reads the place's reef and swell), the boulders (`Rocks.js`), shifts the meadow's dryness
(`TerrainShading.js`, `GrassField.js`), mixes the vegetation groups (`Scatter.js`), and turns the sea floor into a
drop-off or a reef flat (`TerrainData.js` shelf). `TerrainData` adds sheer cliffs (`recipe.cliffs`). With no recipe or
REFERENCE: the heightmap byte-identical (tests/places.test.mjs) and the frames identical
(`research/super-scenic/evidence/places-identity-2-2026-10-12/`).

Removed from the vendored tree (not patches): `public/ui/` (upstream key art). Upstream's `index.html`, `vite.config.js`,
`package*.json`, `test/`, `tools/` and `docs/` are not vendored (the mirror has them).

Unchanged on purpose in wave 1, so the frame comparison holds: the upstream UI (`src/ui/`) and game layer (`src/game/`)
still show upstream's names; the sandbox uses them, games will not (wave 2 track S puts the shared menu and HUD in
front, wave 4 ports fishing as a generic mechanic).

Thin end-to-end wave (track G, 2026-10-12): games boot with `ui: false`, and the game layer is driven by `kit/game.js`
without further core edits: the tables go into the core's table objects in place, the save key is mapped by a storage
wrapper, the core's Game gets a HUD adapter (so it never builds upstream's HUD, minimap or first-play guide), vendor
names and greetings are set from the tables, and the sign texture is painted over from the tables. The frame comparison
after patches 2 and 3: 34/34 shots bit-identical (PSNR 99 dB, 0 % of pixels over tolerance).
